The 5 GeoDjango 500 Errors

1–5 All Return 500: GIS Model Serialization Failure
GET /api/districts/ · GET /api/districts/{id}/ · GET /api/districts/{id}/boundary/ · GET /api/needs/ · GET /api/needs/{id}/

Root Cause

GDAL not installed or migrations incomplete on Render. The Django GIS app tries to serialize geometry fields (PointField, PolygonField) without proper C library support.

Fix Steps

  1. SSH into Render backend
    ssh into your Render backend service
  2. Run all migrations
    python manage.py migrate python manage.py migrate core python manage.py migrate gis
  3. Verify GDAL is installed
    python -c "from django.contrib.gis.gdal import gdal_version; print(gdal_version())"
    If error: GDAL not installed. Edit render.yaml buildCommand to install GDAL before pip install.
  4. Replace serializers.py with fixed version
    Copy: /Users/prantikroy/claude\ code/SETU/backend/core/serializers.py.fixed To: /Users/prantikroy/claude\ code/SETU/backend/core/serializers.py
    The fixed version adds error handling for geometry field serialization using SerializerMethodField
  5. Commit and push changes
    git add backend/core/serializers.py git commit -m "Fix: Add error handling for GIS geometry field serialization" git push
  6. Restart backend service on Render
    Render will auto-redeploy on push. Service restarts with new code.
  7. Test all 5 endpoints
    curl -H "Authorization: Bearer YOUR_TOKEN" \ https://setu-8.onrender.com/api/districts/
    Expected: 200 OK with district list (not 500)

Troubleshooting

Still Getting 500 Errors?

Check 1: GDAL Status
Run in Render console: python -c "from django.contrib.gis.gdal import gdal_version; print(gdal_version())"
If error → GDAL not installed. Update render.yaml buildCommand.
Check 2: Migrations Applied
Run: python manage.py showmigrations core
All should show [X] (applied). If not → run: python manage.py migrate
Check 3: Debug Logs
Set DEBUG=true in Render environment. Check Render dashboard > Backend > Logs for full traceback.
