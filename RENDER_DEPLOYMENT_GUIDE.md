# SETU Render Deployment Guide

This guide explains how to deploy the entire SETU platform (frontend, backend, and database) to Render.

---

## 📋 Prerequisites

- GitHub account with access to the SETU repository
- Render account (free tier available at https://render.com)
- Backend and frontend properly configured (already done)

---

## 🚀 Step-by-Step Deployment

### Step 1: Create a Render Account
1. Go to https://render.com and sign up (free tier available)
2. Connect your GitHub account for easy deployments

### Step 2: Create a New Service from render.yaml
1. In Render dashboard, click **"New +"**
2. Select **"Blueprint"**
3. Paste your GitHub repository URL: `https://github.com/Prantikroy-pixel/SETU.git`
4. Render will automatically detect and use the `render.yaml` configuration
5. Click **"Create from Blueprint"**

### Step 3: Configure Environment Variables

The `render.yaml` already defines most variables. The following will be auto-generated:
- `SECRET_KEY` — generated securely
- `DATABASE_URL` — auto-linked to PostgreSQL instance
- `DJANGO_SUPERUSER_PASSWORD` — generated securely

No additional configuration needed—Render handles everything!

### Step 4: Wait for Deployment

Render will:
1. ✅ Build the backend (Python + Django)
2. ✅ Build the frontend (React + Vite)
3. ✅ Create a PostgreSQL database (free tier)
4. ✅ Deploy both services
5. ✅ Provide you with live URLs

### Step 5: Access Your Deployment

Once complete, you'll see:
- **Frontend URL**: `https://setu-frontend.onrender.com`
- **Backend API URL**: `https://setu-backend-XXXXX.onrender.com`
- **Database**: Auto-connected PostgreSQL

## 🔧 Configuration Details

### render.yaml Overview

```yaml
services:
  - type: web
    name: setu-frontend          # Static frontend on Render
    env: static
    buildCommand: "cd Frontend && npm install && npm run build"
    staticPublishPath: Frontend/dist
    
  - type: web
    name: setu-backend           # Django backend API
    env: python
    startCommand: "cd backend && gunicorn config.wsgi:application ..."
    
databases:
  - name: setu-db               # PostgreSQL instance
    plan: free                  # Free tier (1GB storage)
```

### Django Settings (Already Updated)

The backend has been configured to:
- ✅ Detect Render environment via `RENDER=true`
- ✅ Use PostgreSQL when `DATABASE_URL` is provided
- ✅ Fall back to SQLite for local development
- ✅ Enable CORS for `*.onrender.com` domains
- ✅ Support proper HTTPS proxy headers
- ✅ Auto-migrate database on startup

### Frontend API Configuration (Already Set)

The frontend uses:
- ✅ Relative API paths (empty `VITE_API_URL`)
- ✅ Automatic CORS handling via Axios
- ✅ JWT token refresh logic
- ✅ Mock fallbacks for offline resilience

## 📝 Post-Deployment Steps

### 1. Create Admin User (Optional)

The backend auto-creates a superuser during migration. You can:

```bash
# Via Render Shell (in Render dashboard)
cd backend
python manage.py createsuperuser
```

Or use credentials from environment variables (already set in `render.yaml`).

### 2. Verify Database Connection

```bash
# Check via Render Shell
cd backend
python manage.py dbshell
```

### 3. Test API Endpoints

```bash
curl https://setu-backend-XXXXX.onrender.com/api/auth/me/
```

### 4. Monitor Logs

In Render dashboard:
- Click your backend service
- Go to **"Logs"** to see real-time output
- Check for migrations, errors, or warnings

## 🔐 Security Notes

1. **SECRET_KEY**: Automatically generated by Render (never commit to repo)
2. **ALLOWED_HOSTS**: Restricted to `.onrender.com` (modify in settings if needed)
3. **CORS Origins**: Whitelisted via regex patterns
4. **Database**: PostgreSQL connection via `DATABASE_URL` (encrypted)
5. **Static Files**: Served directly by frontend (WhiteNoise handles backend static files)

## 🐛 Troubleshooting

### Build Failures

Check the build logs in Render:
1. Go to **Deployments** tab
2. Click the failed deployment
3. Review full build log

Common issues:
- **Missing dependencies**: Check `requirements.txt` and `package.json`
- **Build script errors**: Verify `build.sh` permissions (`chmod +x`)
- **Database migrations**: Check `backend/manage.py migrate` command

### Frontend Not Loading

- Clear browser cache (`Ctrl+Shift+Del`)
- Check frontend URL in browser
- Verify CORS settings in `settings.py`

### API Not Responding

- Check backend logs in Render
- Verify `DATABASE_URL` is set
- Test with: `curl https://setu-backend-XXXXX.onrender.com/api/health/`

### Database Issues

- Render provides limited free tier storage (1GB)
- Monitor data usage in Render dashboard
- Older records may need archival
