🐛 The 5 GeoDjango 500 Errors (Unified Fix)

All 5 endpoints fail due to the same root cause: GeoDjango model serialization issues when GDAL is missing or migrations are incomplete.

1-5 GET /api/districts/ + GET /api/districts/{id}/ + GET /api/districts/{id}/boundary/ + GET /api/needs/ + GET /api/needs/{id}/
All return 500 Server Error due to GIS model serialization failure

Root Cause Analysis

  • GDAL C library not installed or misconfigured on Render
  • Missing or incomplete Django migrations for GIS models
  • spatial_compat.py fallback fields not properly initialized
  • DistrictSerializer/NeedSerializer trying to serialize geometry fields without proper handling

Unified Fix: 5 Steps

Step 1: Verify GDAL on Render

Check buildpack includes GDAL support

render.yaml buildCommand should include: pip install --upgrade pip pip install -r requirements.txt python manage.py collectstatic --no-input requirements.txt should have: GDAL==3.8.0 # or latest stable version
ℹ️ Solution: If GDAL not installed, Render needs a custom buildpack or base image with GDAL pre-installed. Add to render.yaml:
buildCommand: | apt-get update && apt-get install -y gdal-bin libgdal-dev pip install --upgrade pip pip install -r requirements.txt python manage.py collectstatic --no-input
Step 2: Run All Migrations

SSH into Render and apply pending migrations

ssh into Render backend python manage.py migrate python manage.py migrate core python manage.py migrate gis
Step 3: Verify Serializers Handle Geometry

Add error handling in backend/core/serializers.py

class DistrictSerializer(serializers.ModelSerializer): boundary = serializers.SerializerMethodField() centroid = serializers.SerializerMethodField() def get_boundary(self, obj): try: if obj.boundary: return obj.boundary.geojson if hasattr(obj.boundary, 'geojson') else None except Exception as e: logger.error(f"Boundary serialization error: {e}") return None def get_centroid(self, obj): try: if obj.centroid: return { "type": "Point", "coordinates": [obj.centroid.x, obj.centroid.y] } except Exception as e: logger.error(f"Centroid serialization error: {e}") return None class Meta: model = District fields = ['id', 'name', 'state', 'boundary', 'centroid', 'population']
Step 4: Add Exception Handling in Views

Wrap GIS queries in try-except blocks

class DistrictViewSet(viewsets.ModelViewSet): def list(self, request, *args, **kwargs): try: return super().list(request, *args, **kwargs) except Exception as e: logger.error(f"Districts list error: {e}") return Response( {"error": "Unable to fetch districts", "detail": str(e)}, status=status.HTTP_500_INTERNAL_SERVER_ERROR )
Step 5: Restart & Test

Restart gunicorn and verify endpoints

curl -H "Authorization: Bearer YOUR_TOKEN" \ https://setu-8.onrender.com/api/districts/ Expected: 200 OK with district list

🆘 Troubleshooting

Still Getting 500 Errors?

Check 1: GDAL Installation

Run in Render console:

python -c "from django.contrib.gis.gdal import gdal_version; print(gdal_version())"

If error: GDAL not installed. Add to render.yaml buildCommand.

Check 2: Migrations

Run in Render console:

python manage.py showmigrations core python manage.py showmigrations gis

All should show [X] (applied). If not, run: python manage.py migrate

Check 3: Debug Logs

Set DEBUG=true and check full error traceback in Render logs
