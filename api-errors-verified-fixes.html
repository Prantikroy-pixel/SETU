Critical Issues: 500 Server Errors

All 5 GeoDjango/GIS endpoints failing with identical root cause. Fixes below address the core issue.

1 GET /api/districts/ Critical
Districts list endpoint returns 500 Server Error (389.8ms)
GET /api/districts/

🔴 Root Cause: GeoDjango model serialization failure. Missing GDAL library or corrupted GIS migrations.

Fix
  • Verify GDAL is installed on Render
  • Run migrations: python manage.py migrate
  • Check District model has proper location field
  • Test with: curl -H "Authorization: Bearer TOKEN" https://setu-8.onrender.com/api/districts/
Debug Step
Run with DEBUG=true on Render to see full traceback in logs
2 GET /api/districts/{id}/ Critical
Individual district detail retrieval fails (482.3ms)
GET /api/districts/{id}/

🔴 Root Cause: Same as Error #1 — GIS model query failing on detail lookup

Fix (Same as #1)
  • Run: python manage.py migrate core
  • Verify District model imports from django.contrib.gis
  • Check backend/core/models.py for LocationField definition
  • Restart gunicorn on Render
3 GET /api/districts/{id}/boundary/ Critical
Boundary geometry retrieval returns 500 error (409.7ms)
GET /api/districts/{id}/boundary/

🔴 Root Cause: GIS boundary serialization + missing geometry data in database

Fix
  • Run all migrations: python manage.py migrate
  • Seed boundary data: python manage.py sync_districts_boundaries
  • Verify GeoDjango installed: check settings.py for 'django.contrib.gis'
  • Test after restart
Note
This endpoint requires SRTM DEM data. If seed command missing, load from shapefile manually.
4 GET /api/needs/ Critical
Needs list endpoint returns 500 error (485.3ms)
GET /api/needs/

🔴 Root Cause: Need model Location field serialization failing (same GIS issue)

Fix
  • Run: python manage.py migrate core
  • Check core/models.py — Need model should have location field
  • Verify serializers properly handle PointField or GeometryField
  • Add try-except in view to catch GIS errors
5 GET /api/needs/{id}/ Critical
Individual need detail retrieval fails (352.2ms)
GET /api/needs/{id}/

🔴 Root Cause: Same as Error #4 — GIS field query failing on detail lookup

Fix (Same as #4)
  • Run: python manage.py migrate
  • Test directly in Django shell: python manage.py shell
  • Try: from core.models import Need; print(Need.objects.first())
  • If error appears, debug serializer

6 All Protected Endpoints (7 total) Expected
Auth-required endpoints return 401 when no token provided
GET /api/auth/me/ PATCH /api/auth/me/ GET /api/auth/users/ POST /api/auth/admin/create-user/ POST /api/auth/users/{id}/verify/ POST /api/districts/sync-boundaries/

✓ Expected Behavior: These endpoints require authentication

Fix
  • Step 1: Login first with POST /api/auth/login/
  • Step 2: Extract access_token from response
  • Step 3: Add header to all requests: Authorization: Bearer {token}
  • Step 4: Verify api.js interceptor is attaching header (lines 634-642)
Workaround in Frontend
api.js already has MOCK fallback for all these endpoints. If API fails, mock data is returned automatically.
